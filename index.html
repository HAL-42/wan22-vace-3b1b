Chapter 0

一个看似贪心的问题

做视频的人每天要面对一长串不同的需求：

用一句话生成视频 让这只猫出现在视频里 按这段舞蹈的姿态重新生成 把画面里的树换成路灯 把视频向两侧扩展 给定首帧和尾帧补中间 把这段视频续写 5 秒

传统做法是：每个任务一个专用模型。那么，能不能只用一个模型做完全部？

VACE（Video All-in-one Creation and Editing）的回答是：可以。只要我们先意识到一件事——

这些任务表面上千差万别，本质上都在回答同两个问题：
哪些像素应该保留？ 哪些像素需要重新画？（以及：重画时参考什么？）

而 Wan2.2 提供的，是一个非常会“画”的视频生成主干。VACE 教它“听指挥”。下面我们先从最底层的直觉开始：模型到底是怎么“画”的。

Chapter 1

从噪声到画面：一条直线上的旅程

想象画面中的每个像素（更准确地说，每个潜变量数值）都是平面上的一个点。一段真实视频就是这些点排成的某种有结构的形状；而纯噪声则是同样多的点随机散落。

Wan 系列采用的 Flow Matching 把两者用最简单的方式连起来——直线插值。拖动下面的滑块，看噪声水平 $\sigma$ 从 1 降到 0 时会发生什么。

σ = 1.000
每个点的位置：$x_\sigma = (1-\sigma)\,x_0 + \sigma\,\epsilon$。黄色箭头是模型需要预测的“速度”——从当前位置该往哪走。

关键在于：生成时模型看不到终点 $x_0$。它只能看着当前这团模糊的点，猜一个方向，迈一小步，再重新看、再猜。训练目标就是让这个猜测尽量准：

$$\mathcal{L} = \mathbb{E}_{x_0,\epsilon,\sigma}\Big\|\, v_\theta(x_\sigma,\ \sigma,\ \text{条件}) - (\epsilon - x_0) \,\Big\|^2$$

采样则是沿着预测速度反向积分（欧拉法）：

$$x_{\sigma-\Delta} = x_\sigma - \Delta \cdot v_\theta(x_\sigma, \sigma, \text{条件})$$
留意一个现象：当 $\sigma$ 很大时，画面几乎全是噪声，模型最合理的猜测只能是大致布局（东西大概在哪）；当 $\sigma$ 很小时，布局已定，模型要做的是补细节。这个“前期定构图、后期抠细节”的观察，第 5 章会变成 Wan2.2 的核心设计。

公式里那个“条件”是整件事的突破口。文生视频时它只是一段文字；而 VACE 要往里面塞进视频、掩码、参考图——任何你想让模型遵守的东西。

Chapter 2

哪里保留，哪里重画：视频条件单元

VACE 把所有任务的输入统一成一个三元组，称为视频条件单元（Video Condition Unit, VCU）：

$$V = [\,T;\ F;\ M\,],\qquad F=\{u_1,\dots,u_n\},\quad M=\{m_1,\dots,m_n\}$$

其中 $T$ 是文本，$F$ 是一组上下文帧（RGB，归一化到 $[-1,1]$），$M$ 是同样尺寸的二值掩码：$1$ 表示“这里需要生成”，$0$ 表示“这里照抄”。

光看公式不够直观。下面是一段 6 帧的小视频（一个小球滚过草地）。选择不同任务，看 $F$ 和 $M$ 如何变化；你也可以直接在掩码行上拖动涂抹。

灰色 = 数值 0（在 $[-1,1]$ 归一化下即中灰）。蓝框：模型必须保留的内容；黄框：模型要重画的区域里“原来是什么”。

为什么要拆成两路？——概念解耦

注意上面最后两行。VACE 不直接把 $F$ 喂进模型，而是用掩码把它切成两份：

$$F_k = F \odot (1-M) \quad(\text{inactive，要保留的}),\qquad F_c = F \odot M \quad(\text{reactive，要改变的})$$

原因是：同一个“视频帧”输入，在不同任务里含义完全相反。做局部编辑时，掩码外的像素是必须原样保留的事实；掩码内的像素则只是“原来长这样，请改掉它”的参考。如果把两者混在一起，模型得自己去猜每个像素的身份；拆开之后，这个信息被显式地告诉了它。

任务上下文帧 $F$掩码 $M$
文生视频 T2V$\{0\}\times n$$\{1\}\times n$
参考生视频 R2V$\{r_1..r_l\}\cup\{0\}\times n$$\{0\}\times l\cup\{1\}\times n$
视频到视频 V2V（姿态/深度/边缘等控制）$\{u_1..u_n\}$（控制信号）$\{1\}\times n$
掩码视频编辑 MV2V（局部重绘、扩展、首尾帧…）$\{u_1..u_n\}$$\{m_1..m_n\}$

更妙的是，这些任务可以自由组合：比如“参考图 + 姿态控制 + 局部掩码”——只需把对应的帧和掩码拼进同一个 VCU。

常见疑问：$F_k$ 与 $F_c$ 到底表示什么？

问：$M$ 把上下文帧分成两种用途：$F_k$ 表示这些上下文要被原样保留（如首尾帧、inpainting 的不变部分）；$F_c$ 表示这部分上下文用于引导条件生成（如深度、姿态）。这个理解对吗？

答：大体正确，但有两处需要修正。

  • $F_k = F \odot (1-M)$：正确。它是 $M=0$ 位置的内容，属于模型必须遵守、不能改动的事实，例如首尾帧、续写的已知帧、inpainting 的掩码外区域。
  • $F_c = F \odot M$：“用于引导生成”不够准确。深度、姿态只是其中一种情况。

划分依据是 $M$，而不是信号类型。$M=1$ 的位置都进入 $F_c$，表示“这里要重新生成，这是它原来的内容”。这些内容起什么作用，取决于 $F$ 里放的是什么：

任务$F_c$ 中的内容对生成的作用
深度 / 姿态 / 边缘控制控制信号（$M$ 全为 1）结构引导
灰度上色灰度视频（$M$ 全为 1）保留亮度结构，重画颜色
inpainting（掩码内）官方预处理把掩码内填成灰色，约等于 0基本不提供信息，内容由文本和周围区域决定
文生视频 / 续写的未知帧全 0不提供任何信息

所以深度、姿态进入 $F_c$，是因为这类任务把 $M$ 设为全 1，而不是因为 $F_c$ 专门用来放控制信号。

$F_k$ 也不总是逐像素照抄。参考生视频（R2V）中，参考图的 $M=0$，因此进入 $F_k$，但它不会原样出现在输出里：它只用来固定主体的身份与外观，解码后对应的参考帧会被去掉。

更准确的说法：$M$ 按“是否允许改变”把上下文帧切成两份。$F_k$ 是不可改变的已知内容，生成时要与之保持一致；$F_c$ 是可以改变区域中放入的信息，其约束强度取决于任务：控制信号起强结构引导作用，灰度视频约束亮度，全零（或灰色填充）则没有信息。
Chapter 3

把条件翻译成模型能读的语言

Wan 的 DiT 主干并不直接处理像素，而是处理 VAE 压缩后的潜变量，再切成 token。VACE 的上下文也要走同样的路，才能与视频 token 一一对齐：

  • $F_k$ 与 $F_c$ 各自经过同一个视频 VAE 编码：时间压缩 4 倍、空间压缩 8×8，得到两个 16 通道的潜变量 $z_k, z_c$。
  • 掩码 $M$ 不过 VAE，而是被“折叠”：每个 8×8 像素块重排成 64 个通道，时间维插值到与潜变量相同的长度，得到 $m'$（64 通道）。
  • 三者沿通道拼接：$16 + 16 + 64 = 96$ 通道，再由上下文嵌入层按 $1\times2\times2$ 切块投影成 token——与视频 token 位置一一对应。

调一调下面的视频规格，感受一下压缩到底有多狠：

按 Wan2.1 VAE（4×8×8，16 通道）计算；Wan2.2 A14B 沿用该 VAE。注意力的计算量随 token 数平方增长，这就是为什么压缩至关重要。

到这里，“条件”已经变成了一串与视频 token 等长的上下文 token $c$。剩下的问题是：怎么把它们交给一个已经训练好的、拥有百亿参数的主干？

Chapter 4

不动主干，开一条旁路

最直接的方法是把上下文 token 加到视频 token 上，然后整个模型重新微调。可以，但代价是：昂贵，而且可能把主干原本出色的生成能力“调坏”。

VACE 选择了另一条路——上下文适配器（Context Adapter）：冻结主干，复制其中若干个 Transformer 块组成一条旁路，专门读上下文 token；旁路每一层的输出（称为 hint）通过一个投影加回主干的对应层。

蓝色：冻结的 Wan DiT 主干块（以 14B 的 40 层为例）。黄色：可训练的上下文块，示意为每隔 5 层注入一次。注入位置的具体配置以各版本权重为准。

用公式写，第 $l$ 个被注入的主干层变成：

$$x_{l} \leftarrow \mathrm{Block}_l(x_{l-1}) + \alpha \cdot W_{\text{out}}\, h_l,\qquad h_l = \mathrm{CtxBlock}_l(h_{l-1})$$

其中 $W_{\text{out}}$ 初始化为零：训练刚开始时旁路对主干毫无影响，模型从“原本会画”的状态出发，逐渐学会“听指挥”。$\alpha$ 是推理时可调的条件强度（代码中常叫 context_scale）。

直觉：α 是一根“牵引绳”

下面是一个示意（并非真实模型输出）：蓝色小人是输入的姿态控制视频，灰色是主干“自由发挥”的动作，黄色是注入后的结果。

α = 1.00
α = 0：完全忽略条件；α ≈ 1：训练时的默认强度；α 过大：条件被“过度执行”，画面容易失真。
这种设计与 ControlNet / Res-Tuning 一脉相承：主干负责“会画”，旁路负责“听话”。因为主干不变，同一套主干权重可以继续用于原来的文生/图生视频，VACE 只是一个可插拔的附加模块。
Chapter 5

Wan2.2：把一位画家拆成两位专家

回忆第 1 章的观察：高噪声阶段定构图，低噪声阶段补细节。这是两种很不一样的工作。Wan2.2 的 A14B 模型干脆让两个模型分工：

  • 高噪声专家：负责去噪前期，决定整体布局与运动；
  • 低噪声专家：负责去噪后期，雕琢纹理与细节。

两个专家结构相同、各约 14B 参数，总计约 27B；但每一步只运行其中一个，所以单步计算量与一个 14B 模型相当。这是一种按时间步切换的混合专家（MoE）：

$$v_\theta(x_\sigma,\sigma,\cdot)=\begin{cases} v_{\text{high}}(x_\sigma,\sigma,\cdot), & \sigma \ge \sigma_b \\ v_{\text{low}}(x_\sigma,\sigma,\cdot), & \sigma < \sigma_b\end{cases}$$

切换点 $\sigma_b$ 由信噪比 $\mathrm{SNR}(\sigma) = \big(\tfrac{1-\sigma}{\sigma}\big)^2$ 决定。采样时还会对时间表做“偏移”（shift）：$\sigma' = \dfrac{s\sigma}{1+(s-1)\sigma}$，让更多步数落在高噪声区。动手试试：

左：横轴是去噪进度（σ 从 1 到 0），纵轴为 log SNR，圆点是实际采样步。右：观察点处的含噪画面（σ 越大，画面越接近纯噪声）。

把 VACE 接到 Wan2.2 上，最自然的做法就是两位专家各配一条上下文旁路：同一组上下文 token 在前期引导构图与运动（例如姿态、深度），在后期约束细节与保留区域的一致性。

说明：Wan2.2 官方仓库并未单独发布 VACE 权重。目前通常所说的 “Wan2.2-VACE” 主要指阿里 PAI 在 VideoX-Fun 中发布的 Wan2.2-VACE-Fun-A14B，它沿用 VACE 的条件机制并接入 Wan2.2 A14B 的双专家主干。具体注入层、训练数据与支持的控制类型请以其仓库说明为准。
Chapter 6

把所有零件拼起来

现在可以完整地走一遍一次推理了：

  • 组装 VCU：根据任务准备文本 $T$、上下文帧 $F$（原视频 / 控制图 / 参考图 / 全零）与掩码 $M$。
  • 解耦与编码：$F_k=F\odot(1-M)$、$F_c=F\odot M$ 分别过 VAE；掩码折叠成 64 通道；拼成 96 通道上下文潜变量。参考图（若有）的潜变量拼在时间维最前面。
  • 初始化：从纯噪声 $x_1\sim\mathcal N(0,I)$ 出发，按 shift 后的时间表准备 $N$ 个 $\sigma$。
  • 选择专家：每一步根据 $\sigma$ 是否高于 $\sigma_b$ 选择高噪声或低噪声专家（各自带着 VACE 旁路）。
  • 预测速度：旁路读取上下文 token 产生 hints，以强度 $\alpha$ 加入主干；主干同时通过交叉注意力读取 umT5 文本特征，输出速度 $v$（通常配合无分类器引导 CFG）。
  • 迈一步：$x \leftarrow x - \Delta\sigma\cdot v$，重复直到 $\sigma = 0$；去掉参考帧对应的潜变量，用 VAE 解码成视频。

对应到代码，大致长这样（简化的伪代码）：

# 上下文：96 通道 = 16 (保留) + 16 (待改) + 64 (掩码)
z_k, z_c = vae.encode(F * (1 - M)), vae.encode(F * M)
ctx      = cat([z_k, z_c, fold_mask(M)], dim=channel)

x = randn_like(latent)
for sigma, dsigma in shifted_schedule(steps, shift):
    expert = high_noise if sigma >= boundary else low_noise

    tok  = expert.patchify(x)
    c    = expert.vace_patchify(ctx)
    c    = expert.before_proj(c) + tok           # 零初始化，与视频 token 对齐
    hints = []
    for blk in expert.vace_blocks:                # 可训练旁路
        c = blk(c, text, sigma)
        hints.append(expert.after_proj(c))     # 零初始化
    for i, blk in enumerate(expert.blocks):      # 冻结主干
        tok = blk(tok, text, sigma)
        if i in expert.vace_layers:
            tok = tok + alpha * hints[expert.vace_layers.index(i)]

    v = expert.unpatchify(tok)                 # 实际中还会做 CFG
    x = x - dsigma * v

video = vae.decode(x)

三句话回顾

1. 生成 = 沿着模型预测的速度，从噪声一步步走向数据（Flow Matching）。

2. 所有编辑与控制任务 = 告诉模型“哪里保留、哪里重画、参考什么”，统一为 VCU $[T;F;M]$，并解耦成 $F_k$、$F_c$。

3. 实现 = 冻结 Wan2.2 的双专家主干，用零初始化的上下文旁路把条件注入进去。

值得记住的边界

  • VACE 只决定“条件怎么进入模型”，最终画质与运动上限仍由主干决定。
  • 掩码保留区域在潜空间被约束，但经过 VAE 解码后边界处仍可能有轻微色差，实践中常配合后处理融合。
  • 条件强度 $\alpha$、shift、切换点等超参会显著影响结果，不同任务往往需要分别调。
Chapter 7

训练数据：从一段普通视频里“出题”

一个模型要学十几种任务，难道要为每种任务收集成对的“输入—输出”数据？VACE 的答案是：不用。几乎所有任务都可以从一段普通视频自动造出来。

思路像老师出填空题：拿一段完整的视频 $x$ 当标准答案，然后挖掉一部分（掩码）或把它变换成另一种形态（深度、姿态、灰度……），得到题目 $(F, M)$。模型的任务就是从题目和文本 $T$ 还原出原视频：

$$x \;\xrightarrow{\ \text{挖空 / 变换}\ }\; (T,\,F,\,M) \;\xrightarrow{\ \text{VACE}\ }\; \hat x \approx x$$

因为答案就是原视频本身，这些数据不需要人工标注，只需要视频、字幕描述和一组现成的视觉工具。

公共流水线：先把视频“读懂”

VACE 论文第 4.1 节描述的公共处理流程如下，各任务的数据都建立在它的产物上：

  • 切镜头与初筛：按镜头切分视频，再按分辨率、美学评分、运动幅度过滤。
  • 首帧打标签与检测：用 RAM 给首帧打标签，再用 Grounding DINO 检测这些物体；目标区域过小或过大的视频被二次过滤。
  • 全片分割跟踪：用 SAM2 的传播功能把首帧的实例分割到整段视频，得到逐帧的实例掩码。
  • 时间维过滤：按掩码面积阈值统计每个实例的有效帧比例，过滤在大部分时间里消失或过小的实例。

得到的是“视频 + 字幕 + 逐帧实例掩码”。下面逐任务看题目是怎么出的。

任务上下文帧 $F$ 怎么造掩码 $M$答案
文生视频 T2V全 0全 1原视频
深度 / 涂鸦 / 姿态 / 光流用现成模型从原视频预先提取全 1原视频
灰度 / 布局训练时即时生成全 1原视频
Inpainting原视频，掩码内置空随机实例的掩码原视频
Outpainting原视频，掩码内置空实例掩码取反原视频
视频扩展（含首帧/首尾帧）挑出的关键帧或片段，其余置空已知帧为 0，其余为 1原视频
参考生视频 R2V从视频中抠出的人脸/物体 + 增强，放在最前面参考帧为 0，视频帧为 1原视频
任务组合随机叠加上面几种对应拼接原视频

1. 文生视频（T2V）

最简单：$F$ 全为 0，$M$ 全为 1，只有文本。它保证加上 VACE 之后，模型在“没有任何上下文”的情况下仍然能正常生成。

2. 可控生成：深度、涂鸦、姿态、光流

对过滤后的视频离线预提取控制信号，并都存成 RGB 视频，这样所有控制都能走同一条输入通道：

  • 深度：单目深度估计模型 MiDaS（论文引用 Ranftl et al.）。
  • 涂鸦（scribble）：线稿生成模型 Informative Drawings（Chan et al.）。
  • 姿态：OpenPose 与 DWPose。
  • 光流：RAFT，再把光流可视化成彩色图。

VCU 为 $F=\{\text{控制帧}\}$、$M$ 全 1，所以控制信号全部进入 $F_c$。答案是原视频：模型学的是“给定这条结构轨迹，画出与之吻合的真实画面”。

为什么要预提取？这些模型较重，逐帧跑一遍代价高，所以提前算好存下来。灰度和布局计算很便宜，就在训练时即时生成。

3. 可控生成：灰度与布局

  • 灰度（上色）：把原视频转成灰度即可，$F$ = 灰度视频，$M$ 全 1。模型要保持亮度结构，补回颜色。
  • 布局：论文只说“即时生成”。从开源预处理工具看，做法是把公共流水线跟踪到的实例框画成逐帧的彩色方框，作为粗粒度的位置与运动轨迹控制。

4. 重绘：Inpainting 与 Outpainting

这里直接复用公共流水线产出的实例掩码：

  • Inpainting：随机选一个实例，用它的逐帧掩码作 $M$。掩码内的像素被置空（官方预处理填成灰色），模型要依据文本和周围画面把这个物体画回来。
  • Outpainting：把实例掩码取反，保留主体、重画周围环境。推理时常见的“向外扩画布”，可以看成掩码覆盖边框的特例。
  • 无条件 inpainting（擦除）：对掩码做 LaMa 风格的增强（随机形状、膨胀等），让掩码不再紧贴某个物体轮廓。这样模型学到的是“自然地补全背景”，而不是“必须在这里画一个物体”。

论文还提到：所有涉及掩码的操作都做了随机增强，以适应各种粒度的局部编辑需求，例如用户只给一个粗糙的框，而不是精确轮廓。

5. 视频扩展：首帧、尾帧、首尾帧、任意帧

这类任务的掩码在时间维上：从原视频挑出若干已知帧，其余帧置空。论文列出的取法有：

首帧 → 图生视频 尾帧 → 倒推前面 首尾两帧 → 插帧过渡 随机若干帧 → 关键帧补全 首/尾一段 → 续写

已知帧的 $M=0$，进入 $F_k$；未知帧的 $M=1$、内容为空。这样一套数据就同时覆盖了 I2V、首尾帧生成和视频续写，不需要单独训练图生视频模型。

6. 参考生视频（R2V）

从视频中抠出若干人脸或物体实例（利用公共流水线的检测与分割结果），作为参考图 $r_1,\dots,r_l$ 放在帧序列最前面，掩码为 0；后面的视频帧为空、掩码为 1。答案仍是原视频。

关键是对参考图做离线或在线增强再配对。论文没有展开原因，一个合理的理解是：参考图直接来自同一段视频，如果不增强，模型可能学会把参考图原样贴到画面里，而不是“认出这个主体，再让它自然地动起来”。增强打破了像素级的对应关系，迫使模型只记住身份和外观。

推理时，官方代码会把参考图等比缩放后放在白色画布中央，这也暗示训练时参考图是“白底主体图”的形式。

7. 任务组合

论文明确说：训练时会随机组合上面的各种任务，例如“参考图 + inpainting”（把视频里的某个物体换成参考图里的主体）、“首帧 + 姿态”等。因为所有任务共享同一个 VCU 格式，组合只是把对应的帧和掩码拼起来，不需要额外设计数据。

训练顺序：由易到难

数据不是一股脑全部混在一起训练的。论文的第 5.1 节描述了分阶段的课程：

  • 基础任务：先训练 inpainting 和扩展。它们与文生视频预训练最互补，让模型先学会掩码的含义，以及在空间和时间上“看上下文生成”。
  • 任务扩展：从单张参考图过渡到多张参考图，从单一任务过渡到组合任务。
  • 质量微调：用更高质量的数据和更长的序列做最后微调。

训练输入支持任意分辨率、可变时长和可变帧率。基于 Wan2.1-T2V-14B 的版本覆盖“12 个任务 + 组合任务”，分辨率约 720p，训练 200k 步。
